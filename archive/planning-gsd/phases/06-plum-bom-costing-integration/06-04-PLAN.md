<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser form → PLUM/SYERP API | User-entered BOM/AVL/price-break values cross to the backend; client validation is convenience only |
| UI gating (Draft vs Released) | Client hides edit controls on Released revisions; the backend 422 is the real authz boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-18 | Spoofing | client-only Draft gating bypass | accept | UI hides edit controls when revisionStatus != 'draft'; backend (Plan 02) enforces the real 422 guard — client gate is convenience only |
| T-06-19 | Tampering | malformed numeric input (qty/cost) | mitigate | Input type=number with min/step constraints; backend Pydantic (gt=0, Numeric) is the authoritative validator |
| T-06-20 | Information Disclosure | cycle/error detail surfaced to user | accept | server error detail surfaced inline is expected UX (cycle message is non-sensitive guidance) |
</threat_model>
