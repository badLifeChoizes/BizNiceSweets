| Token | Value | Usage |
|-------|-------|-------|

| sm | 8px | Button padding (x-axis), list item gaps |

| lg | 24px | Card padding, sidebar section padding |
| xl | 32px | Layout section breaks |

## Typography

Source: shadcn/ui Tailwind defaults, slate base, system font stack.

Exactly 2 font weights are used across the entire phase: **400 (normal)** and **600 (semibold)**.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (text-sm) | 400 (normal) | 1.5 |
| Label | 14px (text-sm) | 600 (semibold) | 1.4 |
| Heading | 20px (text-xl) | 600 (semibold) | 1.2 |
| Display | 28px (text-3xl) | 600 (semibold) | 1.2 |

### Typography application rules

- **Sidebar nav item text:** 14px / weight 600 / line-height 1.4 (Label role)
- **Topbar company name:** 14px / weight 600 — treated as a compact heading, not a display
- **Settings page heading (e.g. "System Settings"):** 20px / weight 600 (Heading role)
- **Settings section subheadings (e.g. "Company Identity", "Locale Defaults"):** 14px / weight 600 (Label role)
- **Form input values and helper text:** 14px / weight 400 (Body role)
- **Admin page titles (/settings/modules):** 20px / weight 600 (Heading role)
- **Empty state message:** 14px / weight 400 (Body role)
- **Tooltip text (always-on explanation):** 12px / weight 400 — shadcn Tooltip default

> Implementation note: use only Tailwind `font-normal` (400) and `font-semibold` (600). Do NOT introduce `font-medium` (500) anywhere in this phase.

## Color

Source: index.css CSS variables, slate base color.

| Role | CSS Variable | Light Mode | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `--background` | hsl(0 0% 100%) = white | Page background, main content area |
| Secondary (30%) | `--secondary` / `--muted` | hsl(210 40% 96.1%) = light slate | Sidebar background, cards, settings panels, topbar |
| Accent (10%) | `--accent` | hsl(210 40% 96.1%) | Active nav item background (NavLink isActive), Switch thumb active state |
| Primary | `--primary` | hsl(222.2 47.4% 11.2%) = dark slate | Primary action buttons ("Save Settings"), filled button backgrounds |
| Destructive | `--destructive` | hsl(0 84.2% 60.2%) = red | Module disable confirmation visual (if shown); no destructive actions in primary flows |
| Muted foreground | `--muted-foreground` | hsl(215.4 16.3% 46.9%) | Disabled module names, placeholder text, nav items for non-current modules |
| Border | `--border` | hsl(214.3 31.8% 91.4%) | Separator lines, input borders, card borders |

### Color application rules

Accent (`--accent` / `bg-accent`) is reserved for these specific elements only:
1. Active nav item background in the sidebar (NavLink isActive state)
2. Active nav item text (`text-accent-foreground`)

The accent color is NOT used for:
- Buttons (use `--primary` for filled, `--secondary` for ghost)
- Form focus rings (use `--ring`)
- Badges or status indicators (use `--primary` or semantic colors)
- Hover states outside the nav (use `--muted`)

### Dark mode

Dark mode CSS variables are defined in index.css (`.dark` class). This phase does not add a theme toggle. The app renders in light mode. Dark mode variables exist and apply if the system prefers dark, per Tailwind's default `prefers-color-scheme` behavior. No explicit dark mode UI work is in scope for Phase 3.

## Component Patterns

### AppShell layout (D-01, D-02)

```
┌──────────────────────────────────────────────────────────┐
│  Topbar (h-12, bg-background, border-b)                  │
│  [≡ mobile] [Company Name]        [user dropdown ▾]      │
├────────────────┬─────────────────────────────────────────┤
│  Sidebar       │  Main content (flex-1, overflow-y-auto) │
│  (w-64, bg-    │  <Outlet />                             │
│  muted/secon-  │  p-4 to p-6                             │
│  dary, hidden  │                                         │
│  md:flex flex- │                                         │
│  col)          │                                         │
└────────────────┴─────────────────────────────────────────┘
```

- Topbar: `h-12`, `border-b`, `bg-background`, `px-4`, flex items-center justify-between
- Sidebar desktop: `hidden md:flex md:w-64 md:flex-col`, `bg-muted/50` or `bg-secondary`, `border-r`
- Sidebar mobile: Sheet side="left", triggered by hamburger icon in topbar (md:hidden)
- Main content: `flex-1 overflow-y-auto p-4` (16px padding)
- Full shell container: `flex h-screen bg-background overflow-hidden`

### Accessibility: icon-only interactive controls

All icon-only controls must carry an accessible label (no visible text fallback):

| Control | Element | Accessible label |
|---------|---------|------------------|
| Mobile sidebar trigger (hamburger) | Sheet trigger button (md:hidden) | `aria-label="Open navigation"` |
| User/admin menu trigger | DropdownMenu trigger (avatar/user icon) | `aria-label="Open user menu"` |

Decorative lucide icons inside labeled controls (e.g. icon beside a text nav label) should carry `aria-hidden="true"`. Icon-only controls must never rely on the icon alone for their accessible name.

### Sidebar nav item states (NavLink)

| State | Class |
|-------|-------|
| Default (inactive) | `text-muted-foreground hover:bg-muted hover:text-foreground` |
| Active (current route) | `bg-accent text-accent-foreground` |
| Disabled (no modules) | renders empty state in content area, not greyed nav items |

Nav item layout: `flex items-center gap-2 rounded-md px-3 py-2 text-sm font-semibold transition-colors`

### User/Admin dropdown (D-03)

DropdownMenu in topbar, right side. Trigger carries `aria-label="Open user menu"`. Items:
- User name + email (non-interactive, separator below)
- "Settings" — links to /settings (admin-only, hidden for non-admin)
- "Modules" — links to /settings/modules (admin-only, hidden for non-admin)
- "Users" — links to /admin/users (admin-only, hidden for non-admin)
- Separator
- "Log out" — triggers logout mutation

Trigger: User avatar initials (2-char) or user icon from lucide-react.

### Module enable/disable table (/settings/modules)

shadcn Table with columns:
- Module name (`display_name`) — Body 14px weight 600 in the cell label
- Status badge — Badge component: "Always On" (secondary variant) or "Enabled"/"Disabled" text
- Enable toggle — Switch component (disabled + tooltip for always_on=true modules)

SYERP row: Switch rendered but `disabled` prop set. Cursor: not-allowed. Tooltip: "SYERP is the core hub and cannot be disabled."

### Settings form (/settings)

Two Card sections:
1. "Company Identity" — fields: Company Name (Input, required)
2. "Locale Defaults" — fields: Currency (Select), Date Format (Select), Timezone (Select), Units (Select)

Form footer: "Save Settings" Button (primary/default variant), right-aligned within card.

## Interaction Contracts

### Nav visibility refetch (D-09)

- `useModules` query: `staleTime: 10_000`, `refetchOnWindowFocus: true`
- Toggle mutation `onSuccess`: `queryClient.invalidateQueries({ queryKey: ['core', 'modules'] })`
- Nav updates within ~1 second of invalidation for the tab that toggled; other tabs update on next window focus

### Loading states

- AppShell auth check (useAuth loading): full-screen centered Loader2 spinner, no nav chrome rendered
- useModules loading within sidebar: sidebar renders with skeleton or empty — do NOT show spinner in sidebar; show module names only once loaded (use `data ?? []` pattern, sidebar renders empty list while loading)
- Settings form loading (useSettings): Input fields show disabled + placeholder text while loading; submit button disabled
- Toggle Switch during mutation: Switch disabled while `toggleMutation.isPending` to prevent double-toggle

### Error states

- Module toggle 422 (always-on): Switch snaps back to enabled=true. Toast: "SYERP cannot be disabled."
- Module toggle 403: Toast: "You don't have permission to change module settings."
- Settings PATCH error: Form fields remain filled. Toast: "Failed to save settings. Please try again."
- Auth failure (AppShell): redirects to /login with `state={{ from: location }}` — existing ProtectedRoute behavior preserved

### Active-module indicator

Use React Router NavLink `isActive` prop. Do NOT compare `window.location.pathname` manually.
Active class applied via `className={({ isActive }) => cn(...)}` pattern.

### Admin-only UI elements

- Settings/Modules/Users items in dropdown: conditionally rendered only when `user.roles.some(r => r.name === 'admin')` is true
- Non-admin users see only "Log out" in the dropdown (and their user name/email)
- Backend is the real gate; UI gating is convenience only
