<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → PATCH /api/v1/core/modules/{key} | Untrusted toggle request; could attempt to disable a core module or act without admin rights |
| client → PATCH /api/v1/core/settings/{key} | Untrusted settings write; could attempt admin config without permission |
| client → GET /api/v1/core/modules | Module catalog read; must not be exposed to anonymous callers |
| client → GET /api/v1/core/settings | Settings read; any authenticated user (shell header needs company.name) but not anonymous callers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-04 | Tampering | PATCH /core/modules/{key} always-on bypass | mitigate | Backend rejects `enabled=false` on `always_on` modules with HTTP 422 — the disabled UI Switch is convenience only. Covered by `test_cannot_disable_always_on`. |
| T-03-05 | Elevation of Privilege | PATCH /core/modules + /core/settings authz | mitigate | All mutation (write) endpoints gated by `require_permission("settings:manage")`; non-admin → 403 (`test_toggle_requires_admin`). Standard `user` role lacks the permission. Settings GET is intentionally any-authenticated (read-only, non-sensitive) — no privilege escalation since no write is exposed and no sensitive field is returned. |
| T-03-06 | Information Disclosure | GET /core/modules + /core/settings anonymous access | mitigate | `Depends(get_current_user)` required on both reads — unauthenticated requests get 401, not the module catalog or settings (RESEARCH Open Questions 1 & 2 RESOLVED). Settings read is exposed to any authenticated user by design: v1 settings are non-sensitive identity/locale defaults (company name, locale), and the shell header (D-02/D-05) must render them for every user; no secrets or per-user private data are stored in global settings. |
| T-03-07 | Tampering | PATCH /core/settings overwriting omitted fields | mitigate | `model_dump(exclude_unset=True)` ensures only explicitly-sent fields are written; omitted fields are not nulled (Pitfall 8). |
| T-03-08 | Tampering | settings value injection (e.g. script in company.name) | accept | Pydantic validates `value` as `str`; React renders it as text (not innerHTML) in 03-03, so stored-XSS is not reachable via the shell header. No HTML sanitization needed server-side in v1. |
</threat_model>
