the existing codebase (Users.tsx, Settings.tsx, AppShell.tsx).

| Token | Value | Tailwind class | Usage |
|-------|-------|---------------|-------|
| xs | 4px | p-1 / gap-1 | Badge gap row, icon-to-label gap |

## Color

All color tokens are CSS custom properties defined in `frontend/src/index.css`.
Do NOT hard-code hex values — use `hsl(var(--token))` via Tailwind semantic
class names. Light and dark mode handled by the existing token set.

| Role | CSS token | Approx. light-mode hex | Usage in this phase |
|------|-----------|------------------------|---------------------|
| Dominant (60%) | `--background` | #ffffff | Page canvas, table rows, sheet panels |
| Secondary (30%) | `--card` / `--muted` | #f1f5f9 (slate-100) | Card surfaces (Settings pattern), muted backgrounds, sidebar nav |
| Accent (10%) | `--primary` | #0f172a (slate-900) | "Create Vendor" button, "Create Customer" button, "Save Changes" button in sheet footer |
| Destructive | `--destructive` | #ef4444 | Archive confirmation button only |
| Borders | `--border` | #e2e8f0 (slate-200) | Table borders, card borders, input outlines |
| Muted text | `--muted-foreground` | #64748b (slate-500) | Descriptions, placeholders, inactive nav items |

Accent (`--primary`, rendered as `variant="default"` Button) is reserved for:
1. "Create Vendor" CTA button (Vendor list toolbar)
2. "Create Customer" CTA button (Customer list toolbar)
3. "Save Changes" / "Save Partner" button inside the PartnerSheet footer
4. Active sidebar nav item background (`bg-accent text-accent-foreground` —
   already set in Sidebar.tsx; applies to the Vendors, Customers, GL nav entries)

Accent is **NOT used** on: archive actions, Cancel/Discard buttons, ghost
action triggers, row-level edit links, CoA tree expand controls.

Source: `frontend/src/index.css` (full token set), `Users.tsx` (`variant="default"` only on Create), `Sidebar.tsx` (`bg-accent` for active state).

Status badge colors (inherited from Users.tsx `StatusBadge` pattern):
- Active partner: `bg-green-50 text-green-600` — always paired with text "Active"
- Archived partner: `bg-gray-100 text-gray-500` — always paired with text "Archived"
- Vendor role badge: `variant="outline"` Badge — consistent with Users.tsx role badges
- Customer role badge: `variant="outline"` Badge

## Screen-by-Screen Interaction Contracts

### Screen 1: Vendor List (`/syerp/vendors`)

**Layout:** Identical to `Users.tsx` — `p-8 space-y-6` content area inside
the AppShell `<main>` (flex-1, overflow-y-auto).

**Toolbar (top):**
- Left: `<Input placeholder="Search vendors…" className="max-w-xs" aria-label="Search vendors" />`
- Left, after input: `<Switch>` labeled "Show archived" — Switch component (installed)
- Right: `<Button variant="default">Create Vendor</Button>` — the only accent element

**Search behavior:**
- Server-side via `GET /api/v1/syerp/partners?role=vendor&q={term}&include_archived={bool}`
- Debounced 300ms (identical to Users.tsx `debounceTimer` pattern)
- Query key: `['syerp', 'partners', 'vendor', { q, includeArchived }]`

**Table columns:**
| Column | Width | Content |
|--------|-------|---------|
| Name | auto | `font-medium` text |
| Code | auto | Monospace-style text (default font, no special class) |
| Contact | auto | `contact_name` or "—" if null |
| Country | auto | ISO alpha-2 or "—" |
| Status | auto | StatusBadge (Active/Archived) — color + text |
| Actions | w-12 | `DropdownMenuTrigger` ghost icon button, 44px touch target |

**Row actions (DropdownMenu):**
- "Edit" → opens PartnerSheet in edit mode
- "Archive" → opens ArchiveDialog (destructive) — shown when `active=true`
- "Restore" → fires PATCH `{active: true}` directly, no confirmation — shown when `active=false`

`aria-label` on trigger: `"Vendor actions for {partner.name}"`

**Loading state:** `<Loader2 className="h-6 w-6 animate-spin text-muted-foreground" />` centered, `py-12`

**Empty state (no data at all):** heading + body (see Copywriting Contract)

**Empty state (search returned nothing):** same empty state component — body text adjusts to include "Clear the filter or…"

### Screen 3: Shared Partner Edit Form (PartnerSheet)

**Container:** `<Sheet side="right">` — right-side drawer (consistent with Users.tsx)

**Sheet title:**
- Create mode: "Create Vendor" or "Create Customer" (parameterized by calling screen)
- Edit mode: "Edit Partner"

**Sheet description:**
- Create Vendor: "Fill in the details to add a new vendor."
- Create Customer: "Fill in the details to add a new customer."
- Edit: "Update the partner record. Changes are audited."

**Form layout:** `div.py-6.space-y-6` with four `<Separator>`-divided sections.
Each section uses `div.space-y-4` containing `div.space-y-2` pairs of Label + Input/Select.

**Section 1 — Identity:**
| Field | Element | Required | Notes |
|-------|---------|----------|-------|
| Name | Input | Yes | `placeholder="Acme Corp"` |
| Code | Input | Yes | Pre-filled by API; user may override. `placeholder="P-0001"` |
| Is Vendor | Switch | — | Labeled "This partner is a vendor" |
| Is Customer | Switch | — | Labeled "This partner is a customer" |

Validation rule: at least one of Is Vendor / Is Customer must be on. If both
are off, disable Save and show inline error below the switches:
`<p className="text-sm text-destructive">At least one role must be selected.</p>`

**Section 2 — Address:**
| Field | Element | Required | Notes |
|-------|---------|----------|-------|
| Address Line 1 | Input | No | `placeholder="123 Main St"` |
| Address Line 2 | Input | No | `placeholder="Suite 400"` |
| City | Input | No | `placeholder="Springfield"` |
| State / Region | Input | No | `placeholder="IL"` |
| Postal Code | Input | No | `placeholder="62701"` |
| Country | Input | No | `placeholder="US"` — ISO alpha-2 |

**Section 3 — Contact:**
| Field | Element | Required | Notes |
|-------|---------|----------|-------|
| Contact Name | Input | No | `placeholder="Jane Smith"` |
| Email | Input type="email" | No | `placeholder="jane@acme.com"` |
| Phone | Input | No | `placeholder="+1 (555) 000-0000"` |

**Section 4 — Commerce:**
| Field | Element | Required | Notes |
|-------|---------|----------|-------|
| Payment Terms | Select | No | Options: "Net 30", "Net 60", "Net 90", "Due on Receipt", "Prepaid" |
| Tax ID (EIN/VAT) | Input | No | `placeholder="12-3456789"` |
| Currency | Select | No | Same options as Settings.tsx CURRENCY_OPTIONS; default from settings API default_currency |
| Country of Origin | Input | No | `placeholder="US"` — ISO alpha-2 |
| Notes | Input (or textarea) | No | `placeholder="Optional notes…"` — use `<textarea>` class-matched to Input style |

**Sheet footer:**
- Left: `<Button variant="outline" onClick={closeSheet} disabled={isSaving}>Discard Changes</Button>`
- Right: `<Button variant="default" onClick={handleSave} disabled={isSaving || roleError}>`
  - Idle: "Save Partner"
  - Saving: `<Loader2 className="animate-spin" />` + "Saving…"

**Currency default behavior:** on create-form mount, fetch `GET /api/v1/core/settings`
(TanStack Query cache hit — already fetched by AppShell chain) and read
`default_currency` setting value. Pre-populate Currency select with that value.
Falls back to "USD" if settings unavailable.

### Screen 4: Chart of Accounts Browse (`/syerp/gl`)

**Layout:** `p-8 space-y-6` — same page padding as other screens.

**Page heading:** `<h1 className="text-xl font-semibold text-foreground">Chart of Accounts</h1>`

**Page description:** `<p className="text-sm font-normal text-muted-foreground">General ledger account structure. Read-only in this version.</p>`

**No toolbar:** no search, no create button, no actions. This screen is
browse-only (D-11 scope guard). No accent elements appear anywhere on this screen.

**Tree rendering:** Use shadcn `<Card>` per account-type group (5 cards:
Assets, Liabilities, Equity, Revenue, Expenses). Each card:
- `<CardHeader>`: type name as `<CardTitle className="text-sm font-semibold">` + account-code range as `<CardDescription>` (e.g. "1000–1999")
- `<CardContent>`: flat indented list using `div.space-y-1`

Account row structure (no interactive expand — the seeded tree is 2 levels
max and small enough to render fully open):
```
div.flex.items-center.gap-3.py-1.5
  span.text-sm.font-mono.text-muted-foreground.w-14  {code}    (e.g. "1110")
  span.text-sm.text-foreground                       {name}    (e.g. "Cash and Cash Equivalents")
  span.text-xs.text-muted-foreground.ml-auto         {type}    (e.g. "ASSET")
```

Top-level group accounts (round hundreds: 1000, 1100, 1200, 2000…) get:
`font-semibold` on name, no indentation.

Sub-accounts get `pl-6` left indent.

**No expand/collapse control needed.** The seeded CoA has at most 2 nesting
levels (type group → sub-accounts) and 40 total accounts — rendering all rows
visible is the correct UX for a small browse table.

**Loading state:** Same `<Loader2>` centered spinner as other screens.

**No empty state:** GL accounts are always seeded on startup. If the API call
fails, show error state (see Copywriting Contract).

## Accessibility Contract

All accessibility rules are inherited from `Users.tsx` (the established
screen contract). The following rules apply to every new screen in this phase.

1. **Every input has a paired Label** via `htmlFor` + `id` (no aria-label
   substitutes for visible form fields).
2. **Sheet has `aria-labelledby` + `aria-describedby`** referencing `SheetTitle`
   and `SheetDescription` ids.
3. **Dialog has `aria-labelledby` + `aria-describedby`** referencing `DialogTitle`
   and `DialogDescription` ids.
4. **DropdownMenuTrigger** has `aria-label="Vendor actions for {partner.name}"`
   (or Customer) on every row.
5. **Archive confirm button** has `aria-label="Archive {partner.name}"`.
6. **StatusBadge uses color AND text** — never color alone. "Active" / "Archived"
   text is always present alongside the background color.
7. **Lucide icons are decorative** in action triggers — paired with
   `<span className="sr-only">` or `aria-hidden="true"` as in Users.tsx.
8. **CoA account rows are not interactive** — plain `div` elements, no
   button/link role. Screen is read-only by design.
9. **Switch components** for "Is Vendor" / "Is Customer" and "Show archived"
   use the shadcn `<Switch>` with a paired `<Label>` (same `htmlFor`/`id` pattern).

### Vendor List / Customer List (identical state set)

| State | Trigger | UI |
|-------|---------|-----|
