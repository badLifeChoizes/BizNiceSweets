<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /api/v1/syerp/* | Untrusted authenticated callers cross into partner/GL data; permission + input validation enforced here |
| `?q=` search param → SQL | User-controlled string reaches the query layer |
| partner id path param → record access | Caller-supplied id selects which record is read/mutated (IDOR surface) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-04 | Tampering | `?q=` ilike search | mitigate | SQLAlchemy parameterized `.ilike(f"%{q}%")` (bound param, not raw-SQL interpolation); verified by search tests |
| T-04-05 | Elevation of Privilege | partner write endpoints | mitigate | `require_permission("syerp:write")` on POST/PATCH; `test_create_requires_syerp_write` asserts 403 without it, 401 unauthenticated |
| T-04-06 | Elevation of Privilege | GL browse endpoint | mitigate | `require_permission("syerp:read")` on `GET /gl/accounts`; `test_gl_requires_syerp_read` asserts 401/403 |
| T-04-07 | Information Disclosure / IDOR | `GET|PATCH /partners/{id}` | accept | Single-tenant self-hosted install; any `syerp:read`/`syerp:write` user is authorized for all partner rows in v1 (no per-record ownership) — risk accepted, documented |
| T-04-08 | Repudiation | partner mutations | mitigate | `write_audit` appends partner.created/updated/archived rows; `test_update_partner_writes_audit` asserts the row exists |
| T-04-09 | Tampering | forced `code` override / collision | mitigate | unique DB constraint + `max_length=20` Pydantic bound + IntegrityError retry; `test_duplicate_code_rejected` asserts rejection |
</threat_model>
