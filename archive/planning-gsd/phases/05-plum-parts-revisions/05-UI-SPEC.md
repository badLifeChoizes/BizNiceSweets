## Spacing Scale

Standard 8-point scale in use across all existing screens. Every screen uses `p-8 space-y-6` as the outermost page wrapper — carry this forward unchanged.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge internal padding, inline label spacing |
| sm | 8px | Compact element spacing, gap between toolbar controls |
| md | 16px | Default form field spacing, card internal padding |
| lg | 24px | Section spacing (`space-y-6` between toolbar / table / timeline blocks) |
| xl | 32px | Page outer padding (`p-8`) |
| 2xl | 48px | Empty state / loading vertical padding (`py-12`) |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Touch-target minimum for icon-only action buttons: 44px (`h-11 w-11`) — matches existing DropdownMenuTrigger pattern.
- Revision timeline connector line: 2px vertical stroke, not on the 8-point scale.

Source: confirmed in `Vendors.tsx`, `Users.tsx`, `AppShell.tsx` — all use `p-8 space-y-6`.

## Typography

Four sizes in use across the project. This phase uses the same four — no new sizes.

| Role | Size | Weight | Line Height | Tailwind Classes | Usage |
|------|------|--------|-------------|-----------------|-------|
| Body | 14px (text-sm) | 400 (normal) | 1.5 | `text-sm text-muted-foreground` | Table cell secondary text, helper copy, badge labels |
| Label | 16px (text-base) | 400 (normal) | 1.5 | `text-base font-normal text-muted-foreground` | Screen subtitles, description paragraphs |
| Heading | 20px (text-xl) | 600 (semibold) | 1.2 | `text-xl font-semibold text-foreground` | Screen `<h1>` ("Parts", "Part Detail") |
| Emphasis | 16px (text-base) | 600 (semibold) | 1.2 | `text-base font-semibold text-foreground` | Empty-state heading, table cell primary value (`font-medium`) |

Two weights only: 400 (normal) and 600 (semibold). `font-medium` (500) is used for primary table cell content per existing pattern — treat as within the 400-600 band.

Source: confirmed across `Vendors.tsx`, `Users.tsx`, `GLAccounts.tsx`.

## Color

Palette is shadcn slate — CSS custom properties set in `src/index.css`. Light mode only in v1 (dark mode variables defined but not toggled by user action).

| Role | CSS Token | Approx Hex (light) | Usage |
|------|-----------|-------------------|-------|
| Dominant (60%) | `--background` / `--card` | #ffffff | Page background, card surfaces, sheet panels |
| Secondary (30%) | `--muted` / `--secondary` | #f1f5f9 | Sidebar, nav hover states, table header row, muted regions |
| Accent (10%) | `--primary` | #1e293b | Reserved elements only — see list below |
| Destructive | `--destructive` | #ef4444 | Archive confirmation button, "Archive" dropdown item only |

Accent (`bg-primary` / `text-primary-foreground`) is reserved for:
1. "Create Part" button (`variant="default"`) in the parts list toolbar
2. Active tab underline in the PlumNav tab strip (`border-primary`)
3. The "Advance Status" button on the Part Detail page when a transition is available

Accent is NOT applied to: row hover, search input focus rings, secondary actions, read-only badge indicators, or the revision timeline.

Status badges use semantic spot color (not accent):
- Draft: `bg-gray-100 text-gray-600` (neutral — work in progress)
- In Review: `bg-yellow-50 text-yellow-700` (caution — pending decision)
- Released: `bg-green-50 text-green-600` (positive — current effective design)
- Obsolete: `bg-gray-100 text-gray-400` (terminal — superseded)
- Archived (part-level): `bg-gray-100 text-gray-500` (consistent with partner archive pattern)

Color is never used alone — status badges always combine color with text label.

Source: `src/index.css` CSS variable block; badge patterns from `Vendors.tsx`, `Users.tsx`.

## Screens and Interaction Contracts

### Screen 1: Parts List (`/plum/parts`)

Layout: `p-8 space-y-6` — identical outer wrapper to Vendors/Users.

Header block:
- `<h1>` — "Parts" at `text-xl font-semibold text-foreground`
- Subtitle — "Manage parts and their revision history." at `text-base font-normal text-muted-foreground`

PlumNav tab strip (mirrors SyerpNav pattern):
- `flex gap-1 border-b border-border`
- Tabs: "Parts" | (Phase 6 will add "BOMs")
- Active tab: `border-primary text-foreground border-b-2 -mb-px`
- Inactive tab: `border-transparent text-muted-foreground hover:text-foreground`

Toolbar (single row, `flex items-center gap-4`):
- Search Input: `max-w-xs`, placeholder "Search part number or description…", debounced 300ms, wires to `?q=` param
- Status filter: shadcn `<Select>` with options: All Statuses | Draft | In Review | Released | Obsolete — wires to `?status=` param (filters on the part's current revision status per D-15)
- Show Archived: `<Switch>` + `<Label>` — "Show archived" — wires to `?include_archived=` param (D-11)
- Create Part: `<Button variant="default">` — "Create Part" — `ml-auto` — opens PartSheet

Table columns:
| Column | Notes |
|--------|-------|
| Part Number | `font-medium`, clickable → navigates to `/plum/parts/{id}` |
| Description | plain text cell |
| Tags | comma-separated classification tag pills or "—" |
| Current Revision | revision label (e.g. "A" or "0.1.0") or "—" if no revision exists yet (impossible by D-03 but guard anyway) |
| Status | revision status badge (Draft / In Review / Released / Obsolete) |
| Actions | `DropdownMenu` with `h-11 w-11` ghost trigger (44px touch target): Edit, Archive / Restore |

Row click (not on Actions cell) navigates to Part Detail. Row height: `h-12`.

### Screen 2: Part Detail (`/plum/parts/:id`)

This is the net-new route (D-14). No existing analog — design is prescriptive below.

Layout: `p-8 space-y-6`

Back navigation:
- `<Button variant="ghost" size="sm">` with `ChevronLeft` icon — "Back to Parts" — navigates to `/plum/parts`

Part header card (`<Card>`):
- `<CardHeader>`: Part number (`text-xl font-semibold`) + Description (`text-base text-muted-foreground`)
- `<CardContent>` two-column grid (`grid grid-cols-2 gap-4`):
  - Classification tags: displayed as inline `<Badge variant="secondary">` pills
  - Current revision label + status badge side by side
  - Created / last updated at `text-sm text-muted-foreground`
- Header actions row (right-aligned): "Edit Part" (`<Button variant="outline" size="sm">`) + "New Revision" (`<Button variant="default" size="sm">`)

Advance Status strip (appears below header card only when the current revision is in Draft or In Review):
- `<div className="flex items-center justify-between rounded-md border border-border p-4">`
- Left: current status badge + arrow icon + target state label (e.g. "Draft → In Review")
- Right: advance button (`<Button variant="default">`) — label maps to transition:
  - Draft → "Submit for Review"
  - In Review → "Release" (and secondary ghost button: "Reject to Draft")
  - Released / Obsolete: strip does not appear (terminal or frozen states)
- The Obsolete state can only be reached automatically (on supersede by a new Release) — no manual "Obsolete" button.

Revision history section:
- `<h2 className="text-base font-semibold text-foreground">Revision History</h2>`
- Timeline list (`<ol>` with `space-y-0`):
  - Each revision is one timeline row
  - Left: 2px vertical connector line in `border-muted` color; top item has no line above; bottom item has no line below
  - Connector dot: 8px filled circle — color matches revision status badge color
  - Row content (right of connector):
    - Revision label (`font-medium text-sm`) + status badge + date (`text-xs text-muted-foreground`)
    - Revision-controlled attributes snapshot: description, category, unit of measure, notes — displayed as a `<dl>` definition list at `text-sm`
    - "Reason for revision" note (free text from D-03 / substitute for ECO) at `text-sm text-muted-foreground italic`
    - If this is not the most-recent revision: diff line "Changed from prior: {field list}" at `text-xs text-muted-foreground` — only lists fields that differ (no diff on first revision)
  - Most-recent revision appears at top; oldest at bottom
  - No expand/collapse in v1 — all rows visible

### Sheet: PartSheet (create / edit part)

Mirrors PartnerSheet pattern: right-side Sheet with `SheetHeader` + sections divided by `<Separator>`.

Sections:
1. Identity
   - Part Number: `<Input>` — auto-prefilled by server, user-editable before save (D-06). Helper text: "System-generated. You may change it before saving."
   - Description: `<Input>` — required. Helper text absent (label sufficient).
2. Classification
   - Tags: multi-select combobox or checkbox group showing seeded vocabulary (Purchased, Manufactured, Assembly, Finished Good, Tool, Raw Material). Zero-or-more (D-12, optional). Label: "Classification Tags"
3. Revision seed (create mode only)
   - "Reason for first revision" note: `<textarea>` or multi-line `<Input>`, optional. Helper text: "Optional. Describe why this part is being created."

Footer: "Cancel" (`<Button variant="outline">`) + "Save Part" (`<Button variant="default">`). Loading state shows `<Loader2 className="animate-spin">`.

### Dialog: NewRevisionDialog

Triggered from "New Revision" button on Part Detail header.

Content:
- `<DialogTitle>`: "Create New Revision"
- `<DialogDescription>`: "A new Draft revision will be created, copying attributes from [source revision label]. You may choose a different source below."
- Clone-from selector: `<Select>` listing all prior revisions by label + status (default: latest Released, fallback to latest overall) — implements D-03 copy-forward
- Reason for revision: `<textarea>` (or `<Input>` multi-line), required
- Footer: "Cancel" + "Create Revision" (`<Button variant="default">`)

### Dialog: ArchivePartDialog

Mirrors PartnerArchiveDialog exactly.

- `<DialogTitle>`: "Archive part?"
- `<DialogDescription>`: "{part.part_number} — {part.description} will be hidden from the parts list. Existing revision history and references are preserved and can be restored at any time."
- Footer: "Keep Part" (`<Button variant="outline">`) + "Archive Part" (`<Button variant="destructive">`)

### Dialog: AdvanceStatusDialog (for In Review → Released only)

Released is irreversible and triggers auto-obsolete of the prior released revision (D-08) — warrants explicit confirmation.

- `<DialogTitle>`: "Release revision {label}?"
- `<DialogDescription>`: "This will release {label} and automatically obsolete the current released revision ({prior_label}). Released revisions cannot be edited."
- Footer: "Cancel" + "Release" (`<Button variant="default">`)

No confirmation dialog for Draft → In Review (low stakes, reversible via Reject).
No confirmation dialog for Reject (In Review → Draft) — direct action + toast.

## Accessibility Contracts

These carry forward from existing screens and are mandatory:

1. Every `<Input>` and `<Select>` has a paired `<Label>` with correct `htmlFor` / `id`.
2. Status badges use color AND text together — never color alone.
3. Icon-only action buttons have `aria-label` and icon has `aria-hidden="true"`.
4. Destructive dialog confirm button has `aria-label="Archive {part_number}"`.
5. The PlumNav strip has `aria-label="PLUM sections"`.
6. The revision timeline `<ol>` has `aria-label="Revision history"` and each `<li>` has implicit list role.
7. The advance status strip "Release" button has `aria-label="Release revision {label}"`.
8. Sheet and Dialog components have `aria-labelledby` pointing to their title element and `aria-describedby` pointing to their description element.
