# Project Rules

## Task Management

Current task is determined by the git branch name. Each task has a checklist file at:

```
docs/tasks/{branch-name}.md
```

If no task file exists for the current branch, create one before starting work.

## Git Workflow

- Branch naming: `feature-*`, `bugfix-*`, `hotfix-*`
- Commits: conventional commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`)
- Commit after completing each checklist item

## Before Every Commit

1. Update the checklist in `docs/tasks/{branch-name}.md`
2. Stage relevant files
3. Write conventional commit message **NEVER** INCLUDE CO AUTHORED POWERED OR GENERATED BY CLAUDE IN MESSAGES
4. Confirm: "✓ Checklist updated | ✓ Committed"

## Before Completing Any Response That Changes Code

Output this line:

```
✓ Task: {branch-name} | Checklist: {x}/{total} complete
```

## Finishing a Task

1. Verify all checklist items are checked
2. Run tests if applicable
3. Move task file to `docs/tasks/_completed/{date}-{branch-name}.md`
4. Create PR: `gh pr create --fill`

## File Structure

```
docs/
└── tasks/
    ├── {active-branch-name}.md    # Current task checklists
    └── _completed/                 # Archived completed tasks
.claude/
└── commands/                       # Slash commands
```

## Prohibited Actions

- Do NOT edit CHANGELOG.md directly (it's generated from commits)
- Do NOT work on code without an active task file
- Do NOT mark a task complete until all checklist items are done
- Do NOT include co authored, powered by or generated with claude in and git commit messages

## Feature Alignment Rules

Before implementing feature code:

1. **Read the relevant feature doc** in `docs/features/`
2. **Reference requirements** - Task checklists for `feature-*` branches MUST reference requirement IDs
3. **Update progress** - When completing a requirement, update `docs/features/requirements-progress.md`
4. **Maintain spec alignment** - If implementation differs from spec, update the feature doc or discuss with user
