# Plan: Phase 12b — GELATO warehouse outbound (pick → pack → ship)
Goal: A warehouse operator can fulfill a Confirmed CRUMB sales order end-to-end — pick reserved lines from bins into a staging bin, pack the shipment, and ship it — where shipping issues staged stock at moving-average cost, relieves the SO's soft-reservation, stamps shipped quantities, and posts a balanced Dr 5100 COGS / Cr 1130 Inventory journal entry atomically with the inventory issue, Trial Balance still netting zero and 1130 tying to the inventory subledger.
Status: draft

## Success criteria
<!-- Traces GELATO-01 AC3 (pick) / AC4 (pack) / AC5 (ship) / AC7 (ship floor + over-ship) / AC8 (audit+RBAC), and SYERP-13 AC1's COGS-on-ship clause. Invoice-from-shipment + AR = Phase 13, NOT here. -->
- **SC1 — Schema + module extension.** Migration **0016** adds `gelato_shipment` + `gelato_shipment_line` tables and `qty_picked` + `qty_shipped` accumulators on `crumb_sales_order_line`; `gelato` still self-registers; `alembic upgrade head` runs 0001→0016 clean on a FRESH DB and round-trips (`downgrade -1`→`upgrade head`); full regression `verify_*` still exit 0. *(prereq for all ACs)*
- **SC2 — Pick (AC3), bin-aware.** Against a Confirmed/Fulfilling SO, a pick list maps order lines → suggested bins holding sufficient on-hand; operator confirms picked qty FROM specific bins; pick posts **bin-aware net-zero** legs (pick-bin → staging bin, same location) via SYERP `post_putaway` and stamps `qty_picked`; per-bin floor guard rejects over-pick 4xx; a non-stock/free-text line (item_id NULL) is rejected 422 (cannot be bin-picked).
- **SC3 — Pack (AC4).** Operator packs the picked shipment (FSM `picking → packed`); partial packs allowed (a ShipmentLine's staged qty may be trimmed ≤ picked); records what is staged to ship.
- **SC4 — Ship (AC5) — the accounting crux.** Ship issues stock from the staging bin at moving-avg cost (**bin-aware negative `InventoryTxn`** via the new SYERP `post_issue`), ATOMIC with one balanced **Dr 5100 COGS / Cr 1130 Inventory** JE (Decimal-exact, ≥2 lines, `source_type="gelato_shipment"`, `commit=False` single-commit); ship decrements the SO line `qty_reserved` (relieves the soft-reservation, keeping `_reserved_by_other_open_sos` accurate) and stamps `qty_shipped`; partial shipments accumulate; ship NEVER over-ships beyond ordered/picked qty (4xx); staging-bin/location on-hand never driven negative (4xx); **1130 control ties to the inventory subledger** and the **Trial Balance nets zero** after the JE; two concurrent ships of the same stock cannot over-issue (**FOR UPDATE lock + `asyncio.Barrier` scenario, proven load-bearing**).
- **SC5 — Audit + RBAC at HTTP level (AC8).** pick/pack/ship each emit attributable audit rows (incl. the ship JE); endpoints gated `gelato:read`/`gelato:write` (401/403/200) — proven by an HTTP-level script (`verify_gelato_ship_api.py`), non-optional. **`write_audit(target_id=str(shipment.id))` — Shipment is int-PK like Bin (the 12a int→VARCHAR bug).**
- **SC6 — Frontend + regression.** Fulfillment UI: a pick/pack/ship flow (a GELATO Fulfillment screen + an affordance from SO detail) — pick lines from suggested bins → pack → ship; nav gated on module-enabled ∩ `gelato:read`; TanStack Query invalidation (bins, unbinned, item on-hand, SO reservation/shortage, shipment); colocated Vitest that **asserts the REAL request payload the endpoint receives**; `npm run build` clean; full regression exit 0 and Trial Balance nets zero.

## Decisions
<!-- D-P12b-1..4 owner-confirmed (fixed constraints); D-P12b-5..9 author calls from the brief; D-P12b-10..13 additional author calls made here with rationale. -->
- **D-P12b-1 (owner) — ONE phase.** Pick + pack + ship + COGS + reservation-relief all in 12b; no 12c split.
- **D-P12b-2 (owner) — Shipment AGGREGATE + FSM.** One `Shipment` header + `ShipmentLine`, lifecycle **picking → packed → shipped** (+ `cancelled` from picking, per D-P12b-11). NOT three separate PickList/Pack/Shipment documents. Shipment → its SO; ShipmentLine → the SO line + the from-bin picked + qty. `source_type="gelato_shipment"` on the ship's ledger/JE rows.
- **D-P12b-3 (owner) — Ledger-consistency debt: OUTBOUND PATH ONLY.** Pick reuses the bin-aware `post_putaway`; ship gets a NEW bin-aware `post_issue` with a NARROW FOR-UPDATE lock (mirror MOUSSE/CRUMB — lock the contended `InventoryItem` rows sorted-id before the floor read). Do **NOT** retrofit `post_adjustment`/`post_transfer`/MOUSSE `issue_components` to be bin-aware, and do **NOT** do the shared-lock refactor — those stay deferred (BACKLOG p2, the cross-path race + bin-blind desync). Stated in Risks and Out-of-scope so 12b doesn't over-reach and a future reader knows the p2 item is only half-closed.
- **D-P12b-4 (owner) — UI folded into this plan, no separate DESIGN.md.**
- **D-P12b-5 (author) — `qty_picked` + `qty_shipped` accumulators on `crumb_sales_order_line`** (Numeric(18,6), server_default 0, mirror `qty_reserved` at `crumb/models.py:426-429`). **Reservation relief happens AT SHIP** (D-V3-11, AC5): ship does `qty_reserved -= shipped_qty` (floored ≥ 0). Picking stamps `qty_picked` only — it does NOT touch `qty_reserved`. Cross-module edit to the CRUMB table by the GELATO ship path is acceptable (GELATO owns fulfillment; imports CRUMB models like MOUSSE imports SYERP). Migration 0016 adds both columns.
- **D-P12b-6 (author) — NEW SYERP bin-aware `post_issue` primitive.** Add to `backend/app/modules/syerp/service/inventory.py`, cloning `post_putaway`'s scaffolding (lock item-master FOR UPDATE before floor read; `get_bin_on_hand` for the source/staging bin; `_adjustment_violates_floor`; value at `moving_avg_cost`) but posting a SINGLE signed `-qty` `issue` leg carrying `bin_id`, `source_type`, `source_id`, with a `commit: bool = True` param so ship can call `commit=False`. GELATO imports it; GELATO never writes `InventoryTxn` directly. Do NOT refactor MOUSSE to use it (deferred paydown).
- **D-P12b-7 (author) — COGS JE mirrors MOUSSE `issue_components`** (`mousse/service.py:743-760`), swapping **1140→5100**: resolve `_gl_account_id_by_code(db,"5100")` and `"1130"`, `post_journal_entry(..., lines=[{account_id:cogs,debit:val,credit:0},{account_id:inv,debit:0,credit:val}], source_type="gelato_shipment", source_id=shipment.id, commit=False)`, valued at moving-avg, `db.flush()` the issue txns first, single `db.commit()`. Atomic with the issue (SYERP-13 AC1).
- **D-P12b-8 (author) — Branch `feature-gelato-pick-pack-ship`** cut off the verified 12a tip (tag `zj/good-12a-gelato-bins-putaway`, `52eb481`). 11a/11b/12a unmerged; 12b stacks. Per the 12a precedent the branch may be cut off the docs-on-top HEAD that is code-identical to the tag, so this PLAN.md isn't dropped (a deliberate Deviation, not a plan violation).
- **D-P12b-9 (author) — Staging bin designation.** `Shipment.staging_bin_id` FK (int, `gelato_bin.id`), operator-selected at pick time from the location's active bins; the pick-list offers a suggestion (a bin whose code marks it staging if present, else the first active bin). NO new `is_staging` flag on `gelato_bin` — any active bin can serve as staging (D-P12a-11). Pick moves pick-bin→`staging_bin_id` (net-zero); ship issues from `staging_bin_id`.
- **D-P12b-10 (author) — Pick auto-advances the SO `confirmed → fulfilling`** on the first pick of an SO (a plain status write, `SO_TRANSITIONS` permits it; `advance_sales_order_status:537-540`). Rationale: the SO is being worked; surfacing "fulfilling" is the truthful state and matches the existing FSM. Ship does NOT auto-close.
- **D-P12b-11 (author) — Shipment FSM `picking → packed → shipped`, plus `cancelled` reachable only from `picking`.** Cancel-from-picking reverses staged picks (staging→pick-bin net-zero via `post_putaway`, restoring `qty_picked`) — mirrors SO cancel's release. A `packed`/`shipped` shipment cannot be cancelled (a shipped issue is a posted GL fact; reversal is a Phase-13+ concern). `SHIPMENT_TRANSITIONS` dict mirrors `SO_TRANSITIONS` shape.
- **D-P12b-12 (author) — Ship never auto-closes the SO.** `fulfilling → closed` stays a manual operator action (existing FSM); partial/backorder shipments are normal and Phase-13 invoicing keys off close. Recommendation carried; flagged (non-blocking) under Decisions needed for owner awareness.
- **D-P12b-13 (author) — NEW `verify_gelato_ship_api.py`** (not extending `verify_gelato_api.py`) — keeps the ship RBAC/audit surface a self-contained script mirroring `verify_mousse_api.py`, and leaves the 12a script untouched for a clean regression baseline.

## Risks
- **Cross-path bin-blind desync stays OPEN for adjust/transfer/MOUSSE-issue (standing BACKLOG p2 — D-P12b-3).** 12b makes ONLY the outbound pick/ship path bin-aware; `post_transfer`/`post_adjustment`/MOUSSE `issue_components` still write `bin_id=NULL` and floor-guard per-location, so a bin-blind draw after stock is binned still overstates the bin it left and can drive the unbinned pool negative — SEQUENTIALLY, not just under a race (the 12a upgraded-MAJOR finding). Location totals and the Σ(bins)+unbinned==location roll-up stay exact; only the split lies. Early-warning: a staging-bin on-hand that disagrees with the item's total after a mixed adjust+ship sequence. Mitigation: 12b closes the outbound half (pick/ship are bin-aware); the retrofit + shared-lock refactor remain deferred and MUST be stated so a reader knows the p2 item is only half-closed. This phase MUST NOT be read as closing it.
- **Migration 0016 touches TWO core-adjacent tables — `crumb_sales_order_line` (add columns) + new gelato tables.** A bad column/FK could break SO reservation/detail or every inventory-derived path. Early-warning: any regression script in task 12 failing, or the SO detail 500ing. Mitigation: `server_default="0"` backfills existing SO lines; task 12 runs the FULL suite; the new columns are additive and unread by existing queries.
- **Reservation double-relief if ship is re-run.** Ship decrements `qty_reserved`; a second ship of the same shipment would double-relieve and over-issue. Early-warning: `_reserved_by_other_open_sos` drifting negative-ward, or a shipped shipment re-shipping. Mitigation: ship is allowed ONLY from `packed` and flips to terminal `shipped` (D-P12b-11); re-ship is 409; scenario (e) in task 10 pins it and task 11 proves it through HTTP.
- **Atomicity of issue + COGS JE.** If the issue commits without the JE (or vice versa) inventory and GL diverge. Early-warning: a `gelato_shipment` issue txn with no linked JE, or a 1130 balance not tying to the subledger. Mitigation: single `commit=False`/`db.flush()`/single-`db.commit()` shape copied verbatim from MOUSSE `issue_components`; task 10 scenarios (b)+(f) assert both the balanced JE and the control-vs-subledger tie (not merely TB nets zero).
- **Concurrency: two ships over-issuing the same staging stock.** Early-warning: negative staging-bin on-hand under load. Mitigation: `post_issue` locks the item-master row FOR UPDATE before the floor read; task 10 scenario (g) Barrier proves it load-bearing (fails when the lock is removed).
- **Verify green but dead-through-UI (11a/11b/12a recurring).** If the ship verify feeds a synthetic shape instead of the real `PickRequest`/`ShipRequest`, or the FE test asserts a hand-built payload, a UI-dead feature certifies green. Mitigation: tasks 10/14 explicitly drive/assert the real router/UI payload; task 11 exercises the real HTTP endpoints.

## Noticed
