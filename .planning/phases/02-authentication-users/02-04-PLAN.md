<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser JS → access token | In-memory only; never persisted to localStorage |
| SPA → backend (dev proxy) | Same-origin via Vite proxy so httpOnly refresh cookie flows |
| admin UI → /auth/users | Client renders admin actions; backend enforces the gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-18 | Information Disclosure | access token storage | mitigate | In-memory module variable only (token.ts); no localStorage/sessionStorage — XSS cannot persist-exfiltrate |
| T-02-19 | Information Disclosure | refresh cookie in dev | mitigate | Vite same-origin proxy + withCredentials so cookie stays httpOnly; no token handed to JS |
| T-02-20 | Elevation | client-side access control bypass | mitigate | UI gating is convenience only; backend require_permission("users:manage") is the real gate (403 verified in plan 03); UI never trusted for authz |
| T-02-21 | Tampering | concurrent refresh race | mitigate | Single-flight isRefreshing flag + failed-queue (RESEARCH.md Pitfall 4) prevents token-rotation self-logout |
</threat_model>
