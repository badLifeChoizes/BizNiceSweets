## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| env → seed | Admin bootstrap creds enter via environment on startup |
| admin request → /auth/users | Privileged user-management actions cross here |
| service → audit_log | Security events recorded for the medical-device posture |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-13 | Elevation | first-admin bootstrap | mitigate | Idempotent seed; no public signup (signup_enabled=false); admin password from SecretStr env, hashed before persist |
| T-02-14 | Elevation | /auth/users privilege escalation | mitigate | Every /users route gated by require_permission("users:manage"); non-admin → 403 (verified in tests) |
| T-02-15 | Elevation | deactivated user retains access | mitigate | Deactivation deletes/revokes RefreshToken rows (D-05); get_current_user is_active check stops access-token reuse within ≤15 min |
| T-02-16 | Repudiation | unlogged admin actions | mitigate | AuditLog append-only rows on user create/update/deactivate/role-change + login events (D-14); no update/delete endpoint on audit_log |
| T-02-17 | Tampering | role/permission seeded as code vs data | mitigate | Roles/permissions are DB rows (D-09) — admin changes are auditable and migration-free; no hardcoded enum bypass |
</threat_model>
