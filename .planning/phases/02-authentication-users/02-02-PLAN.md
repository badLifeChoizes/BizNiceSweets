<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → /auth/login | Untrusted credentials cross here over OAuth2 password form |
| browser cookie → /auth/refresh | httpOnly refresh token returns automatically; replay surface |
| Authorization header → gated endpoints | Bearer access token validated by get_current_user |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-06 | Spoofing | /auth/login | mitigate | Verify Argon2id hash; timing-safe via DUMMY_HASH on user-not-found; 401 reveals nothing distinguishing |
| T-02-07 | Information Disclosure | refresh token storage / transport | mitigate | httpOnly + Secure (prod) + SameSite=Lax cookie scoped to /api/v1/auth/refresh; only SHA-256 hash stored in DB |
| T-02-08 | Tampering / CSRF | /auth/refresh | mitigate | SameSite=Lax + path-scoped cookie; same-origin SPA in prod; refresh requires the cookie, not a header |
| T-02-09 | Elevation | rotated-token replay | mitigate | rotate_refresh_token reuse detection revokes the entire token family on replay |
| T-02-10 | Elevation | deactivated user with live access token | mitigate | get_current_user checks `is_active` on every request (≤15-min stale window accepted; refresh path killed) |
| T-02-11 | Elevation | broken access control on gated routes | mitigate | require_permission("module:action") → 403; admin role wildcard; the single enforcement surface for all modules |
| T-02-12 | Elevation | JWT brute-force / no rate limit | accept | Known ASVS V2.1.9 gap; self-hosted internal deployment; flagged for a later hardening phase (RESEARCH.md Brute-force gap) |
</threat_model>
