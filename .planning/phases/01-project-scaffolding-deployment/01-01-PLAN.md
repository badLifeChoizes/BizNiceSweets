## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env → backend config | DB credentials enter via environment / `.env`; untrusted-at-rest secret material crosses into the process |
| HTTP client → /health/* | unauthenticated liveness/readiness probes (intentionally public, no sensitive data) |
| Alembic CLI → PostgreSQL | migration runner connects with DB credentials at startup |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `Settings.postgres_password` | mitigate | Type password as `pydantic.SecretStr` so it is redacted in repr/logs; never log `settings` or the password; DB URL properties call `.get_secret_value()` only when building the connection string |
| T-01-02 | Information Disclosure | `alembic.ini` | mitigate | No hardcoded `sqlalchemy.url` in `alembic.ini`; URL injected at runtime in `env.py` from env-sourced settings (no secret committed to repo) |
| T-01-03 | Tampering | DB access in health/readiness | mitigate | Readiness uses parameterless `text("SELECT 1")` (no user input); all future queries use SQLAlchemy ORM / parameterized statements — no string-interpolated SQL |
| T-01-04 | Information Disclosure | `/health/ready` error detail | mitigate | On DB failure return a 503 without leaking credentials/host internals in the detail string (generic "Database unavailable") |
| T-01-05 | Denial of Service | migration concurrency | accept | Single-instance self-hosted deployment (D-09); no multi-replica migration race. Documented constraint to revisit if scaling (RESEARCH Security Domain) |
| T-01-06 | Information Disclosure | OpenAPI `/docs` exposure | accept | `/docs` exposes only scaffolding endpoints (health) this phase; no auth/data endpoints yet. Revisit gating in Phase 2 when authed routes appear |
</threat_model>
