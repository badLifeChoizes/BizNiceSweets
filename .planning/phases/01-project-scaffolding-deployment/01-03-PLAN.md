<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator host → compose | operator supplies `.env` secrets at deploy time |
| public network → published ports | only `api:8000` is intentionally published; db must not be |
| image build → registry/base images | base images and pinned deps enter the supply chain |
| container → PostgreSQL | api/entrypoint connect with credentials over the internal compose network |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-10 | Information Disclosure | DB credentials in image | mitigate | No secrets in Dockerfile/ENV; `POSTGRES_PASSWORD` supplied via `env_file: ../.env`; `.env` gitignored, `.env.example` placeholder only; `.dockerignore` excludes local `.env` |
| T-01-11 | Elevation of Privilege | container runs as root | mitigate | Dockerfile creates and switches to a non-root `appuser`; rootless Podman further constrains host privileges |
| T-01-12 | Information Disclosure | Postgres exposed to host/network | mitigate | `db` service has NO `ports:` mapping — reachable only on the internal compose network; not published to the host by default |
| T-01-13 | Tampering | dependency / base-image supply chain | mitigate | Pin runtime deps (`requirements.txt`) and frontend deps (`npm ci` against lockfile); pin base images (`postgres:17-alpine`, `python:3.13-slim`, `node:22-slim`) |
| T-01-14 | Denial of Service | migration on every startup | mitigate | Alembic is idempotent (`upgrade head` is a no-op when current); single-instance deploy (D-09) avoids multi-replica race; entrypoint waits for DB readiness before migrating |
| T-01-15 | Tampering | startup migrates an untrusted/forked schema | accept | Self-hosted single-operator trust model; operator controls the image and DB. Revisit auditable one-shot migration service if medical-device audit needs grow (Deferred Idea) |
| T-01-16 | Information Disclosure | `/docs` publicly reachable | accept | Phase-1 scaffolding only exposes health endpoints; gate `/docs` behind auth in Phase 2 when data/authed routes exist |
</threat_model>
