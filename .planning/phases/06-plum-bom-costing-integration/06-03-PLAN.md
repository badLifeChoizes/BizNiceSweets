<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client upload → import parser | Untrusted .json / .xlsx files cross here; parsing and size are attack surface |
| import data → DB transaction | Imported rows become DB writes; FK integrity and never-delete must hold |
| export endpoint → client | Full dataset (including costs) leaves the system; must be RBAC-gated and audited |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-11 | Denial of Service | oversized import upload | mitigate | import endpoints reject content > 10 MB with 413 before parsing |
| T-06-12 | Tampering | malicious Excel formula/macro | mitigate | openpyxl load_workbook(read_only=True, data_only=True) — values only, no formula execution, no external links |
| T-06-13 | Tampering | import overwrites/deletes unrelated records | mitigate | upsert on stable keys; commit_import NEVER hard-deletes rows absent from the file (D-17); preview shown before commit (D-18) |
| T-06-14 | Tampering | import AVL references non-SYERP vendor | mitigate | validate_import (two-pass) flags unknown vendor_code as a blocking ImportRowError before commit |
| T-06-15 | Information Disclosure | mass cost/price exfiltration via export | mitigate | export gated require_permission("plum:read"); plum.exported audit event on every export |
| T-06-16 | Elevation of Privilege | unauthorized import write | mitigate | import preview + commit gate require_permission("plum:write") |
| T-06-17 | Tampering | SQL injection via import row values | mitigate | all writes use SQLAlchemy ORM parameterized inserts; no raw string interpolation |
</threat_model>
