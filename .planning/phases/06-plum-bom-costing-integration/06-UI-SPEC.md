# Phase 6 — UI Design Contract

> Visual and interaction contract for PLUM BOM, Costing & Integration.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
> Requirements: PLUM-04 (BOM tree), PLUM-05 (flat BOM), PLUM-06 (where-used),
> PLUM-07 (AVL vendor linking), PLUM-08 (cost + roll-up), PLUM-09 (margin),
> PLUM-10 (JSON/Excel import/export).
>
> Phase 6 extends Phase 5 surfaces — do NOT re-specify what Phase 5 already
> locked. Every Phase-5 contract carries forward unchanged unless explicitly
> overridden here.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui |
| Preset | slate base color, default style, CSS variables, no prefix |
| Component library | Radix UI (via shadcn) |
| Icon library | lucide-react (already installed) |
| Font | System font stack (Tailwind default — no custom font) |

Source: `frontend/components.json` (unchanged from Phase 5).

---

## Spacing Scale

Identical to Phase 5. No exceptions added.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, BOM tree indent unit |
| sm | 8px | Compact element spacing, gap between toolbar controls |
| md | 16px | Default form field spacing, card internal padding |
| lg | 24px | Section spacing (`space-y-6` between page sections) |
| xl | 32px | Page outer padding (`p-8`) |
| 2xl | 48px | Empty state / loading vertical padding (`py-12`) |
| 3xl | 64px | Not used in this phase |

Exceptions carried forward from Phase 5:
- Icon-only action buttons: 44px minimum touch target (`h-11 w-11`).
- Revision timeline connector: 2px vertical stroke (not on 8-point scale).

Phase-6 additions:
- BOM tree indent per level: `pl-6` (24px) per depth level. At 5 levels deep the
  left indentation is 120px — acceptable for v1; no horizontal scroll guard needed
  at this depth. Beyond 5 levels tested behavior is undefined (deferred).
- Price-break table rows: `h-10` (40px) — slightly tighter than the 48px parts
  table default because the editor is always inside a card, not a full-page table.

---

## Typography

Four roles unchanged from Phase 5. No new sizes or weights.

| Role | Size | Weight | Line Height | Tailwind Classes | Usage |
|------|------|--------|-------------|-----------------|-------|
| Body | 14px (text-sm) | 400 (normal) | 1.5 | `text-sm text-muted-foreground` | BOM line secondary text, AVL notes, cost helper copy |
| Label | 16px (text-base) | 400 (normal) | 1.5 | `text-base font-normal text-muted-foreground` | Section subtitles, description paragraphs |
| Heading | 20px (text-xl) | 600 (semibold) | 1.2 | `text-xl font-semibold text-foreground` | Screen `<h1>` headings |
| Emphasis | 16px (text-base) | 600 (semibold) | 1.2 | `text-base font-semibold text-foreground` | Section sub-headings (`<h2>`), empty-state headings, rolled-up total values |

Two weights only: 400 (normal) and 600 (semibold). `font-medium` (500) is
permitted for primary table cell content only (Part Number, BOM child part number)
per Phase-5 pattern.

Monospace exception: cost / price numeric values are displayed in `font-mono
text-sm` to align decimal points in the price-break editor and BOM costing column.

## Color

Palette is shadcn slate — CSS custom properties from `src/index.css`. Unchanged
from Phase 5.

| Role | CSS Token | Approx Hex (light) | Usage |
|------|-----------|-------------------|-------|
| Dominant (60%) | `--background` / `--card` | #ffffff | Page background, card surfaces, BOM tree background, import modal |
| Secondary (30%) | `--muted` / `--secondary` | #f1f5f9 | Table header rows, section dividers, BOM odd-row alternation (optional), "unreleased child" row tint |
| Accent (10%) | `--primary` | #1e293b | Reserved elements only — see list below |
| Destructive | `--destructive` | #ef4444 | "Remove BOM line" action, "Remove vendor link" action — dropdown items and confirmation dialogs only |

Accent (`bg-primary` / `text-primary-foreground`) is reserved for:
1. "Add Part" / "Save" primary CTA buttons in the BOM line editor sheet.
2. "Add Vendor" primary CTA button in the AVL editor.
3. "Link Vendor" and "Select for Costing" call-to-action buttons in the AVL panel.
4. "Import" final commit button in the import flow.
5. Active tab underline in PlumNav (`border-primary`) — carried from Phase 5.
6. "Submit for Review" / "Release" advance-status buttons — carried from Phase 5.

Accent is NOT applied to: expand/collapse tree toggle icons, BOM tree rows,
cost display numbers, flat BOM view, where-used results, price-break table rows,
or any read-only data surface.

Status badge color contract (unchanged from Phase 5):
- Draft: `bg-gray-100 text-gray-600`
- In Review: `bg-yellow-50 text-yellow-700`
- Released: `bg-green-50 text-green-600`
- Obsolete: `bg-gray-100 text-gray-400`
- Archived (part-level): `bg-gray-100 text-gray-500`

New semantic indicators (Phase 6):
- Unreleased child warning: `bg-amber-50 text-amber-700` badge next to the child
  part label in the BOM tree ("Unreleased" label). This is a semantic caution
  state, not destructive, so amber is appropriate — consistent with "In Review".
- Preferred vendor badge: `bg-blue-50 text-blue-700` ("Preferred") in the AVL
  list — distinguishes the sourcing preference from the costing selection.
- Selected-for-costing indicator: a `CheckCircle` lucide icon in
  `text-green-600` next to the selected vendor+break row. Icon must be accompanied
  by `aria-label="Selected for costing"`.
- Cost divergence notice (D-14 live-vs-frozen): displayed as a `text-amber-600
  text-xs` note inline below the released cost: "Current cost would be $Y".

Color is never used alone — badges and indicators always include a text label or
`aria-label`.

## Screens and Interaction Contracts

Phase 6 adds three new tab destinations in PlumNav and extends PartDetail.

### PlumNav Tab Strip (extended)

The existing `PlumNav.tsx` must gain two additional tabs:
- "Parts" (existing, routes to `/plum/parts`)
- "Import / Export" (new, routes to `/plum/import-export`)

BOM / AVL / cost surfaces live on `PartDetail` (not as separate top-level routes)
so they do not require new PlumNav tabs.

---

### Extended: Part Detail (`/plum/parts/:id`)

The Phase-5 PartDetail receives four new sections inserted **below the revision
history** section, each in its own `<Card>`:

1. BOM Tree (PLUM-04 / PLUM-05)
2. AVL / Vendor Links (PLUM-07)
3. Cost & Margin (PLUM-08 / PLUM-09)
4. Where-Used (PLUM-06)

Each section uses a consistent card header pattern:
```
<Card>
  <CardHeader className="pb-2">
    <div className="flex items-center justify-between">
      <h2 className="text-base font-semibold text-foreground">{Section Title}</h2>
      {primary action button, if any — variant="outline" size="sm"}
    </div>
  </CardHeader>
  <CardContent>…</CardContent>
</Card>
```

The section order is fixed. All four cards render for every part (including
purchased parts with no BOM children). If a section has no data it shows its
own empty state within the card.

---

#### Section 1 — BOM Tree (PLUM-04 / PLUM-05)

**Card header:** "Bill of Materials" + "Add Part" button (`variant="outline" size="sm"`)
— shown only when the current revision is Draft (immutable when Released, per D-01).

**BOM tree view (default):**

An expandable indented tree rendered as a recursive `<ul>` list.

Each BOM line row:
- Indent: `pl-6` × depth level (depth 0 = no indent, depth 1 = 24px, etc.)
- Toggle icon: `ChevronRight` (collapsed) / `ChevronDown` (expanded) — 16×16px,
  only shown if the child itself has children. Leaf nodes have no toggle.
  - `aria-expanded` attribute must track state.
  - `aria-label="Expand {child_part_number}"` on the toggle button.
- Child part number: `font-medium text-sm text-foreground` (monospace not required
  — part numbers are alphanumeric codes, not numeric values)
- Child revision label + status badge: resolves to latest Released revision per
  D-02; if no Released revision exists, shows latest Draft revision with
  "Unreleased" badge (`bg-amber-50 text-amber-700`)
- Quantity: `font-mono text-sm text-foreground` — decimal format, right-aligned
  in its column. The UoM abbreviation follows immediately in `text-muted-foreground`
  (e.g. "2.5 kg", "12 ea")
- Reference designators: `text-xs text-muted-foreground` in the same row,
  truncated to 48 characters with ellipsis if longer; full value shown on hover
  via `title` attribute.
- Effective cost: `font-mono text-sm text-foreground` — shows the child's
  effective cost (per D-07 resolution chain). If uncosted, shows "—" in
  `text-muted-foreground`.
- Row actions (Draft revision only): `DropdownMenu` with `h-11 w-11` ghost
  trigger (`aria-label="Actions for {child_part_number}"`): "Edit Line" (opens
  BomLineSheet) and "Remove" (destructive — opens inline confirmation, not a
  full dialog).
- Row actions (Released revision): none — all actions hidden, rows are read-only.

Tree rows are NOT clickable for navigation — clicking a child part number opens a
`<Tooltip>` with the part description, not a navigation event. (Navigation would
be disorienting from within the BOM tree. Cross-navigation to the child's own
PartDetail is a Phase 7+ enhancement.)

All items are expanded by default on first load. Expand/collapse state is local
React state, not persisted.

**Flat BOM toggle:**

Above the tree, a toggle control switches between Tree and Flat views:
```
<div className="flex gap-1 border-b border-border mb-4">
  <button
    className={viewMode === 'tree'
      ? 'pb-2 border-b-2 border-primary text-foreground text-sm font-medium'
      : 'pb-2 border-b-2 border-transparent text-muted-foreground text-sm'}
    onClick={() => setViewMode('tree')}
  >
    Tree
  </button>
  <button
    className={viewMode === 'flat'
      ? 'pb-2 border-b-2 border-primary text-foreground text-sm font-medium'
      : 'pb-2 border-b-2 border-transparent text-muted-foreground text-sm'}
    onClick={() => setViewMode('flat')}
  >
    Flat
  </button>
</div>
```

**Flat BOM view (PLUM-05):**

A `<Table>` with columns: Part Number | Description | Total Qty | UoM | Effective Cost | Extended Cost.

- "Total Qty" = rolled-up quantity across all levels (Σ of all paths to this part).
- "Extended Cost" = Total Qty × effective unit cost.
- Table footer row: "Total BOM Cost" spanning all columns, showing the top-level
  roll-up value in `font-semibold font-mono`.
- Parts with no released revision are shown with the "Unreleased" badge.
- The flat BOM is read-only — no edit actions in this view.

**Remove BOM line (inline confirmation, Draft only):**

No dialog. Instead, the row shows an inline "Are you sure?" confirmation in the
Actions column:
```
[Remove] → row enters confirmation state:
  "Remove {child_part_number}? " [Yes, Remove] [Keep {child_part_number}]
```
Both confirmation actions are `size="sm"` buttons. "Yes, Remove" is
`variant="destructive"`. "Keep {child_part_number}" is `variant="ghost"`. This
avoids a dialog for a single-row operation.

**Empty state (no BOM lines):**
```
<p className="text-sm text-muted-foreground text-center py-6">
  No parts added yet.
</p>
<p className="text-xs text-muted-foreground text-center">
  Add child parts to build a bill of materials for this revision.
</p>
```

**BOM line sheet (BomLineSheet):**

Right-side Sheet (mirrors PartSheet pattern).

Fields:
- Child Part: server-side search combobox. Placeholder "Search by part number or
  description…". Debounced 300ms. Shows results as a dropdown list with part
  number (`font-medium`) + description (`text-muted-foreground text-sm`).
  Required. Validation: cycles blocked — if the selected part would create a cycle,
  show an inline error: "Adding {part_number} here would create a circular BOM.
  Choose a different part."
- Quantity: `<Input type="number" step="0.001" min="0.001">`. Required. Decimal
  allowed (supports 0.5 kg, 2.3 m per D-04). Label: "Quantity".
  Helper text: "Decimal quantities are supported (e.g. 0.5, 2.3)."
- Unit of Measure: read-only display of the child part's UoM from its current
  revision — shown as a `text-sm text-muted-foreground` note next to the
  quantity field. Not editable here.
- Reference Designators: `<Input>` optional. Placeholder "e.g. R1, C4, U7".
  Helper text: "Optional. Comma-separated designator identifiers."

Footer: "Discard Line" (`variant="outline"`) + "Save Line" (`variant="default"`).
Loading state shows `<Loader2 className="animate-spin">`.

#### Section 2 — AVL / Vendor Links (PLUM-07)

**Card header:** "Approved Vendor List" + "Add Vendor" button (`variant="outline" size="sm"`).

The AVL section is part-level data (not revision-controlled per D-11: the AVL list
+ price-breaks are live). The selected-vendor+break choice is revision-controlled
and read-only on Released revisions.

**AVL list:**

Each vendor link is displayed as an expandable row in a `<div>` stack (not a
`<Table>`) to allow the price-break table to nest inside cleanly.

Vendor row:
- Left: `ChevronRight` / `ChevronDown` (16px) toggle to show/hide price-break
  table; vendor name (`text-sm font-medium text-foreground`); "Preferred" badge
  (`bg-blue-50 text-blue-700 text-xs`) if `preferred = true`.
- Center: vendor's part number (`text-sm text-muted-foreground font-mono`).
- Right: three-dot `DropdownMenu` (`h-11 w-11` ghost trigger,
  `aria-label="Actions for {vendor_name}"`):
  - "Edit" — opens AVL link sheet
  - "Remove" — destructive dropdown item; opens confirmation dialog

**Price-break sub-table (expanded state):**

Rendered below the vendor row as a `<Table>` with columns:
Qty Threshold | Unit Cost | Lead Days | Actions

- Qty Threshold: `font-mono text-sm` right-aligned.
- Unit Cost: `font-mono text-sm` right-aligned, prefixed with currency symbol.
- Lead Days: `text-sm text-muted-foreground`.
- Actions (Draft revision selected-vendor choice): a radio-button-style
  "Select for Costing" indicator per row:
  - Selected row: `CheckCircle` icon in `text-green-600` with
    `aria-label="Selected for costing"`. The row background tints to
    `bg-green-50` (subtle selection indicator).
  - Unselected row: `Circle` icon in `text-muted-foreground`. Clicking it
    changes the selected vendor+break for the current Draft revision.
  - Released revision: the `CheckCircle` / `Circle` column is read-only (no
    click handler); selection locked at release per D-14.
- Price-break rows are editable inline via the AVL link sheet (not row-level
  inline edit).

**Selected-for-costing display on Released revision (D-14 dual-cost surface):**

Below the vendor's price-break table, when the part is Released:
```
<div className="mt-2 text-xs text-muted-foreground">
  Released at: <span className="font-mono text-foreground">${frozenCost}</span>
  {liveCost !== frozenCost && (
    <span className="text-amber-600 ml-2">Current would be ${liveCost}</span>
  )}
</div>
```

This fulfills D-14: "UI MUST additionally surface the live/current recomputed
cost alongside the frozen one."

**AVL link sheet (AddVendorSheet / EditVendorSheet):**

Right-side Sheet.

Fields:
- Vendor: server-side search combobox (searches `syerp_partner` where
  `is_vendor=true` and `active=true`). Required. Shows vendor code + name.
  Placeholder "Search vendor…".
- Vendor Part Number: `<Input>` optional. Label "Vendor Part Number".
  Helper text: "The supplier's part number or catalog reference."
- Preferred: `<Switch>` + `<Label htmlFor="avl-preferred">Preferred vendor</Label>`.
  Helper text: "Mark this vendor as a preferred sourcing option. Multiple preferred
  vendors are allowed."
- Notes: `<Input>` optional. Label "Notes". Placeholder "e.g. lead time notes".

Price-break section (within the same sheet):
- Sub-heading: `<h3 className="text-sm font-semibold text-foreground mt-4">Price Breaks</h3>`
- Inline editable rows — each row has:
  - Qty Threshold: `<Input type="number" min="1">` (integer)
  - Unit Cost: `<Input type="number" step="0.01" min="0">` (decimal)
  - Lead Days: `<Input type="number" min="0">` (integer, optional)
  - Remove row: `Trash2` icon button (16px, `aria-label="Remove price break"`)
- "Add Price Break" text button (`variant="ghost" size="sm"` with `Plus` icon):
  appends a new empty row.
- Rows sorted by qty ascending; sort is enforced on save, not on input.

Footer: "Discard Changes" (`variant="outline"`) + "Save Vendor Link" (`variant="default"`).

**Remove vendor link confirmation dialog:**

- `<DialogTitle>`: "Remove vendor link?"
- `<DialogDescription>`: "This will remove {vendor_name} from the approved vendor
  list for this part. Existing revision cost data is not affected."
- Footer: "Keep Link" (`variant="outline"`) + "Remove Link" (`variant="destructive"`)

**Empty state (no AVL entries):**
```
<p className="text-sm text-muted-foreground text-center py-6">
  No approved vendors yet.
</p>
<p className="text-xs text-muted-foreground text-center">
  Link a vendor to track sourcing options and vendor-driven pricing.
</p>
```

#### Section 3 — Cost & Margin (PLUM-08 / PLUM-09)

**Card header:** "Cost & Margin"

No add/edit button in the card header. Cost fields are edited via the
"Edit Cost" inline section within this card (Draft revisions only).

**Cost display layout:**

A two-column key-value grid (`grid grid-cols-2 gap-4 text-sm`):

| Label | Value |
|-------|-------|
| Material Cost | `font-mono` — manual entry; editable on Draft, read-only on Released |
| BOM Roll-up Cost | `font-mono` — computed (Σ children × qty); always shown even if manual cost is set (per D-07 user expectation: "surface both") |
| Effective Cost | `font-mono font-semibold` — resolution chain winner per D-07; labeled "Effective Cost (source)" where source is one of: "vendor price", "manual", "roll-up", or "uncosted" in `text-muted-foreground text-xs` |
| Sale Price | `font-mono` — optional; editable on Draft |
| Margin | `font-mono` — computed: Sale Price − Effective Cost; shown only when both values are set |
| Margin % | `font-mono` — computed: Margin / Effective Cost × 100%; shown only when Margin is computable |

**Released revision cost display (D-14):**

When the revision is Released, the Effective Cost row additionally shows:
```
<p className="text-xs text-muted-foreground mt-0.5">
  Released at: <span className="font-mono text-foreground">${frozenCost}</span>
  {liveCost !== frozenCost && (
    <span className="text-amber-600 ml-1">· Current: ${liveCost}</span>
  )}
</p>
```

**Edit Cost inline (Draft revisions only):**

Below the cost grid, a compact inline form (not a Sheet or Dialog):
- Material Cost: `<Input type="number" step="0.01" min="0" className="w-36 font-mono">`
  Label "Material Cost". Helper text: "Optional. Leave blank to use vendor price
  or BOM roll-up."
- Sale Price: `<Input type="number" step="0.01" min="0" className="w-36 font-mono">`
  Label "Sale Price". Helper text: "Optional. Used to compute margin."
- "Save" (`<Button variant="outline" size="sm">`) — saves both values together.

The inline form is always visible on Draft revisions (not hidden behind an "Edit
Cost" button) to reduce friction for the primary costing workflow.

**Margin display:**

When Sale Price and Effective Cost are both available, margin renders below the
edit form as:
```
<div className="mt-3 rounded-md border border-border p-3 text-sm">
  <div className="flex justify-between">
    <span className="text-muted-foreground">Sale Price</span>
    <span className="font-mono">${salePrice}</span>
  </div>
  <div className="flex justify-between">
    <span className="text-muted-foreground">Effective Cost</span>
    <span className="font-mono">${effectiveCost}</span>
  </div>
  <div className="flex justify-between border-t border-border pt-2 mt-2 font-semibold">
    <span>Margin</span>
    <span className="font-mono">${margin} ({marginPct}%)</span>
  </div>
</div>
```

Negative margin (cost exceeds price): the Margin row uses `text-destructive
font-semibold` to signal the anomaly. No other error treatment.

**Currency:**

All costs display the system currency code suffix (e.g. "USD") in
`text-xs text-muted-foreground` after the first monetary amount in each card
section. Not repeated on every row to avoid clutter. Per D-10: single currency,
no FX.

**Empty state (no cost data, no BOM children):**
```
<p className="text-sm text-muted-foreground text-center py-4">
  No cost data yet.
</p>
```
Not shown when Draft with the inline edit form visible (form presence is
sufficient signal).

#### Section 4 — Where-Used (PLUM-06)

**Card header:** "Where Used"

No CTA button (read-only section).

**Where-used display:**

A flat list (not a tree) of parent assemblies that directly or indirectly use
this part. Each row:
- Parent part number: `text-sm font-medium text-foreground`
- Parent revision label + status badge (inline, same row)
- Relationship type: `text-xs text-muted-foreground` — "Direct parent" or
  "Indirect via {immediate_parent_part_number}"
- Rows are NOT clickable for navigation in v1.

The list is sorted: direct parents first, then indirect (breadth-first from
nearest to furthest), then alphabetical within each tier.

**Empty state (part is not used in any BOM):**
```
<p className="text-sm text-muted-foreground text-center py-4">
  This part is not used in any assembly.
</p>
```

**Warning for deep trees (informational, not an error):**

If where-used returns more than 20 results, show a notice above the list:
```
<div className="rounded-md border border-border p-3 text-xs text-muted-foreground mb-3">
  Showing {count} assemblies. This part is used extensively across the product
  structure.
</div>
```

### New Route: Import / Export (`/plum/import-export`)

A standalone page (not a Sheet or Dialog) because import has a multi-step flow
(D-18: upload → preview → commit).

**Layout:** `p-8 space-y-6` (standard page wrapper).

**PlumNav tab:** "Import / Export" — links to `/plum/import-export`.

**Page heading:**
- `<h1 className="text-xl font-semibold text-foreground">Import / Export</h1>`
- `<p className="text-base font-normal text-muted-foreground">Move data in and out of PLUM.</p>`

---

#### Export Panel

A `<Card>` with header "Export".

Two export buttons, stacked vertically in the card:
- "Export as JSON" (`<Button variant="outline">` with `Download` lucide icon) —
  triggers `GET /api/v1/plum/export/json` and streams a file download.
- "Export as Excel" (`<Button variant="outline">` with `FileSpreadsheet` lucide icon) —
  triggers `GET /api/v1/plum/export/excel` and streams a file download.

Loading state during export: button shows `<Loader2 className="animate-spin">`.

Below the buttons, a `text-xs text-muted-foreground` note:
"JSON export is the full lossless dataset. Excel export is a human-friendly
multi-sheet workbook (Parts, BOMs, AVL)."

No confirmation dialog for export — it is read-only.

---

#### Import Panel

A `<Card>` with header "Import".

The import flow is a 3-step sequence rendered inline (not a wizard with
separate pages):

**Step 1 — Upload:**

```
<div className="border-2 border-dashed border-border rounded-md p-8 text-center">
  <Upload className="h-8 w-8 text-muted-foreground mx-auto mb-2" />
  <p className="text-sm text-foreground font-medium">Drop a JSON or Excel file here</p>
  <p className="text-xs text-muted-foreground mt-1">or</p>
  <Button variant="outline" size="sm" className="mt-2" onClick={…}>
    Choose File
  </Button>
  <input type="file" accept=".json,.xlsx" className="sr-only" ref={fileInputRef} />
</div>
```

Accepted formats shown as `text-xs text-muted-foreground` below the drop zone:
"Accepted: .json, .xlsx"

After file selection: display the selected filename in `text-sm font-medium
text-foreground` with a `X` (close/clear) icon button to deselect.

"Upload and Preview" button (`variant="default"`) — becomes active when a file
is selected. Shows `<Loader2>` while the server validates.

**Step 2 — Preview:**

After successful upload, the upload panel is replaced by the preview panel
(same card, not a new page).

Preview summary banner:
```
<div className="rounded-md border border-border p-4 space-y-1 text-sm">
  <p><span className="font-semibold">{newCount} new</span> records will be inserted</p>
  <p><span className="font-semibold">{updatedCount} existing</span> records will be updated</p>
  {errorCount > 0 && (
    <p className="text-destructive font-semibold">{errorCount} errors must be resolved before import</p>
  )}
</div>
```

Error table (if any errors exist):

A `<Table>` with columns: Row | Field | Error Message.
- "Row" column: row number from the source file (`text-sm font-mono`).
- "Field" column: field name (`text-sm text-muted-foreground`).
- "Error Message" column: human-readable problem description (`text-sm text-foreground`).
- Table is scrollable at max-height `max-h-64 overflow-y-auto`.

If any errors exist: "Confirm Import" button is disabled. A note reads:
`text-xs text-destructive`: "Resolve all errors before importing. Correct the
source file and upload again."

If no errors: "Confirm Import" button (`variant="default"`) is enabled.

"Back to Upload" text link (`variant="ghost" size="sm"`) allows the user to
restart with a different file.

**Step 3 — Committed:**

After successful commit, the import card shows a success state:
```
<div className="text-center py-8 space-y-2">
```

## Accessibility Contracts

All Phase-5 contracts carry forward. Phase-6 additions:

1. BOM tree expand/collapse buttons: `aria-expanded={isExpanded}` attribute required;
   `aria-label="Expand {child_part_number}"` or `aria-label="Collapse {child_part_number}"`.
2. BOM tree as a whole: `<ul role="tree" aria-label="Bill of Materials">` with each
   level using `<li role="treeitem">`.
3. "Selected for costing" indicator: `CheckCircle` icon accompanied by
   `aria-label="Selected for costing"` on its container.
4. "Preferred" badge: supplemented by `title="Preferred vendor"` attribute.
5. "Unreleased" badge: supplemented by `title="No Released revision — using latest Draft"`.
6. Import file input: visually hidden but accessible — `<input type="file" className="sr-only">`
   with associated `<label>` containing the drop-zone content.
7. Import error table: `<Table aria-label="Import validation errors">`.
8. Price-break rows: each `<Input>` within the price-break editor has `aria-label`
   including its row index (e.g. `aria-label="Quantity threshold, row 1"`).
9. Inline BOM remove confirmation: the "Yes, Remove" button has
   `aria-label="Confirm remove {child_part_number} from BOM"`. The "Keep
   {child_part_number}" button has `aria-label="Keep {child_part_number} in BOM"`.
10. Flat BOM table: `<Table aria-label="Flat bill of materials">`.
11. Where-used list: `<ul aria-label="Where used">`.
12. Color is never used alone — all semantic indicators (amber unreleased, blue
    preferred, green selected) always include a text label or `aria-label`.
13. BOM line row actions three-dot trigger: `aria-label="Actions for {child_part_number}"`.
14. AVL vendor row actions three-dot trigger: `aria-label="Actions for {vendor_name}"`.
